# MCP-сервер "au"

Даёт агентам-игрокам четыре инструмента к моду AUBridge: `au_state`, `au_wait`, `au_act`, `au_reflex`
(ТЗ — `mod/SPEC-body.md`). Код работает на ПК, ноутбук запускает его по SSH (stdio).

- Python 3.12, venv `D:\AmongUs-tools\mcp\.venv`, пакет `mcp` 1.x (`mcp<2`: во 2-й версии FastMCP переименован).
- Файлы на ПК: `D:\AmongUs-tools\mcp\server.py`, логи `D:\AmongUs-tools\mcp\logs\mcp-ГГГГММДД.log` (без ключей и токенов).
- Запуск: `ssh pc D:/AmongUs-tools/mcp/.venv/Scripts/python.exe D:/AmongUs-tools/mcp/server.py` (см. `.mcp.json`).

## Ключи мест
`powershell -File D:\AmongUs-tools\bridge\new-seats.ps1` пишет `bridge\seats.json` (10 ключей по 32 байта hex, на экран не выводит).
Оркестр читает файл и выдаёт ключ только агенту этого места. Каждый вызов инструмента сверяет `key` с файлом
(`hmac.compare_digest`); при неверном ключе ответ всегда `access denied`. Токены моста (`bridge\tokens\p<id>.txt`)
сервер подставляет сам.

## Поведение
- Конкурентно: каждый запрос — отдельная задача asyncio. К мосту места — два TCP-соединения на 127.0.0.1:47000+id
  (одно для команд, одно для `au_wait`), переподключение при обрыве, закрытие после 90 с простоя.
- Моста нет → `{"ok":false,"error":"bridge offline"}`; мост завис → `bridge timeout`.
- Проверки: player 1..10, timeout ≤ 55, чат ≤ 100 символов, `do` и тип рефлекса из белого списка,
  args ≤ 2 КБ и без служебных имён (`cmd`, `token`, ...), ответ ≤ 48 КБ.

## Ограничения
- Шифрования между ноутбуком и ПК нет, кроме SSH (Tailscale). Ключи мест лежат на ПК в открытом виде.
- Мост допускает 4 соединения на место; одновременно запущенные несколько копий сервера (по одной на агента)
  занимают по 1-2 соединения каждая, поэтому на одно место должен ходить один сервер.
- Параметры args пробрасываются в мост как есть (после проверки имён); их смысл проверяет мод.
